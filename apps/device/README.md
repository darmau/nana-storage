# nana-device：在自己的电脑上处理照片

[English](README.en.md) · 简体中文

开着它的时候，上传的照片由这台电脑处理（缩略图、预览、指纹、人脸、视频转码），**不启动 Cloudflare 容器**。处理代码和云端容器是同一份（`apps/processor/lib.mjs`，同一个 Dockerfile），结果完全一样。

## 使用

需要 Docker Desktop。在 Docker Desktop 的设置里，给它尽量多的 CPU 和内存（Resources），并行处理时每个任务最多会用 1–2 GB 内存。

```bash
cd apps/device
docker compose up -d --build
```

云端关掉了人脸识别（构建变量 `NANA_FACES=off`）的话，这里也要用同样的值构建：`NANA_FACES=off docker compose up -d --build`，否则这台电脑处理的照片有人脸、云端处理的没有。

打开 <http://localhost:7878>：

1. 在“设置”（右上角的齿轮，第一次打开时会自动进入）里填相册的地址（比如 `https://photos.example.com`）、设备名、并行任务数（默认是 Docker 可用 CPU 的 3/4，内存不够时调低）。
2. 点“登录”，在浏览器里打开显示的链接，用相册的账号登录（和平时登录相册一样，走 Cloudflare Access）。登录凭据存在 Docker volume 里，过期后界面会提示重新登录。
3. 登录之后它会自动接管（“转移到设备端执行”）。之后在浏览器里正常上传照片，排队的任务都由这台电脑处理。相册的“设置 › 后台处理”会显示“由设备 … 处理中”。

设备看到的服务器队列只有数量，没有文件名。

停止：`docker compose stop`（或者点“交还云端”）。手上的任务会退回服务器，交还给云端容器。电脑突然关机、断网时，约 2 分钟后服务器自动回到云端容器，接管期间留下的任务在下一个整点由 Cron 补发。

## 相册：浏览和上传（推荐）

界面左边是相册，右边是正在进行的任务（上传进度、正在处理、最近完成）。“相册”和网页版一样：可以进入文件夹、子文件夹，看照片缩略图。**在哪个文件夹，就上传到哪个文件夹**：点“上传文件”“上传文件夹”，或者直接把文件、文件夹拖到页面上（文件夹按目录结构建子文件夹）。同名的 HEIC + MOV 合成 Live Photo、RAW + JPEG 合成一张、重复的跳过，和网页上传一样。

- 设备在接管时，上传的照片直接在这台电脑上处理，**不再从服务器下载一遍原图**，也不需要挂载原图目录；没有接管时由云端容器处理（会产生容器费用），界面会提示。
- 文件由这个页面读取后交给本机程序，**发送期间不要关闭页面**；关掉了的话，重新选择剩下的文件（已经传过的会作为重复跳过），或者点“取消剩下的”。
- 这个界面没有自己的登录：设备登录过相册之后，能打开这台电脑 `localhost:7878` 的人都能浏览照片（端口只绑定本机，局域网里的其他设备打不开）。
- 暂存的文件最多占 4 GB 磁盘，满了会等这台电脑处理完再继续；处理完、取消或交还云端后都会删除。

## 本机原件（可选，省掉下载）

用浏览器在相册里上传的照片，如果原图还在这台电脑（或者它能访问的 NAS）上，可以把目录只读挂进容器，处理时直接读本地文件，不再从服务器下载一遍：

```bash
cp compose.override.example.yaml compose.override.yaml   # 改成自己的目录，可以挂多个
docker compose up -d --build
```

- 启动时在后台建索引（只记文件大小和文件名，不读内容），界面“启动以来”下面会显示索引了多少个文件。找不到的文件最多每 5 分钟重新扫一次，新拷进来的文件也能用上。
- 按大小找候选（同名的优先，文件名不同也行，比如照片库导出时改了名），复制到临时目录时算 sha256，和上传时记下的一致才用。
- 用之前还会让服务器对 R2 上存的那份算一次 sha256（在 Cloudflare 机房里，不经过你的网络），也一致才用。这一步代替了下载后的完整性校验：上传时读盘出错的话，本地文件是对的、R2 上的却是坏的，必须查出来。对不上就照旧下载，任务按原来的规则失败。
- 超过 2 GB 的文件服务器不算校验和（Worker 的 CPU 时间有上限），照旧下载。
- 任何一步出错都退回下载，不会因为本地文件让任务失败。

## 它是怎么工作的

- 身份：用你自己的 Access 登录（`cloudflared access login`），和浏览器访问相册一样，服务器端没有任何额外的账号、令牌或后门。
- 接管：每次认领任务都续一个 2 分钟的租约；租约有效时服务器的队列消费者不启动容器，任务留在数据库里等这台电脑来取。没有任务时每 10 秒问一次（同时续租），一直开着每天约 8,640 次请求，费用可以忽略。
- 处理：下载原件 → 本地处理 → 把缩略图、预览、H.264 预览上传到服务器指定的位置 → 服务器用和容器完全相同的代码写入数据库。处理期间照片被旋转过之类的情况，服务器会发现结果过时，重新处理一次，不会写错。
- 失败：和容器一样每个任务最多尝试 3 次。连续失败 5 次时自动交还云端（多半是本机环境的问题）。
- 安全：界面只绑定本机（`127.0.0.1:7878`），并校验 Host 头。原件只在处理期间放在容器的临时目录里，处理完就删。

## 开发

本地 `wrangler dev` 时，站点地址填 `http://host.docker.internal:8787`（不需要登录）。

```bash
cd apps/device && node --test test/*.test.mjs   # 不需要 Docker 的部分（不在 pnpm 工作区里）
```
